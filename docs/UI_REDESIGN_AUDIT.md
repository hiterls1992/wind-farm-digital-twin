## 1. 当前页面结构与主要功能

单页应用，无构建工具。页面由五层叠加组成：

| 层 | 元素 | 尺寸（1680 × 940 实测） |
|---|---|---|
| 顶部 | `.topbar` 品牌条 + 坐标两行 | 64 px |
| 左 | `.panel-left` 场址概况（4 个 block，共 15 行 + 3 条注释） | 308 px |
| 右 | `.panel-right` 机位清单（8 行）+ 常驻详情块 | 330 px |

**场景可用宽度约 1042 px，占视口 62%**，与"场景为主体"的目标存在差距。左右两栏合计 638 px 常驻，是第一视觉干扰源。

现有功能清单（均已实现且可验证）：

2. 机位选择（场景点选 / 清单点击），相机飞行到单机前视。
3. 每台风机上方 HTML 数据看板（编号、容量、双风速、上网电量、等效小时、轮毂海拔、2000 坐标）。
4. 8 个底图源切换（Esri 影像 / 天地图中文注记 / Sentinel-2 / 晕渲 / 地形图 / 街道图）。
5. 叶轮旋转动画与转速调节、图层开关（边界/道路/集电线路/看板）。
6. 加载遮罩、致命错误提示、底图失败回退提示。

## 2. Cesium 场景的创建与更新机制

- 单 `Cesium.Viewer`，`baseLayer: false`，自建 `CustomHeightmapTerrainProvider`（32 × 32 瓦片，回调内做三级双线性融合）。
- 全部实体用 `Entity`（共 **207 个**，其中叶片分段 box 96 个）。叶片位置/姿态由 `CallbackProperty` 每帧求值。
- 每帧 `scene.postRender` 执行 `updateBoards()`：8 次 `Cartesian3.distance` + 8 次 `worldToWindowCoordinates` + 写 8 个 `style.transform`，并做一次 O(n²) 屏幕避让。
- 相机取景用 `flyToBoundingSphere` + `HeadingPitchRange`，偏移量按场区包围球半径给出。

## 3. 数据加载路径

```
风场数据/风电场.xlsx
  → src/import_windfarm.py → data/site.json        （坐标反算、容量反算、间距校核、凸包边界）
  → src/fetch_dem.py       → data/dem.json         （以机位重心为原点的三级 DEM）
  → src/build_js_data.py   → data/site-data.js     （地形统计、机位 DEM 高程/坡度、融合权重）
  → window.SITE_DATA       → js/app.js
```

底图不落到数据文件，由 `js/app.js` 内 `BASEMAPS` 数组定义，运行时按索引 0 动态挂载 `ImageryLayer`。

## 6. 可能影响性能的代码

- **叶片 CallbackProperty × 96**：每帧 96 次 `bladeLocal` + 矩阵乘 + 四元数解算。实测帧率尚可，但这是唯一随帧增长的 CPU 开销，改造时**不增加**同类回调。
- `CustomHeightmapTerrainProvider` 回调内每瓦片 1024 次三级插值，加载期 CPU 峰值明显，属地形方案固有成本。
- `updateBoards` 每帧写 DOM transform：8 个元素，可接受；**新增看板必须复用同一循环，不得另起监听器**。
- 无重复 Viewer、无重复 `ScreenSpaceEventHandler`、无泄漏的 `setInterval`。当前资源管理是干净的。

## 7. 必须保护的核心逻辑（禁止改动）

1. `src/coord2000.py` 的投影反算（子午线弧长积分 + 牛顿迭代）、带号 38 / 中央经线 114°E 的判定。
2. `enuToLonLat` / `lonLatToEnu`（椭球曲率半径法）与 `heightAt`（三级融合）——**公式逐行不得改动**。
3. 机位实测高程 `t.ground`（数据表 Z）为塔筒起算面；轮毂海拔 = Z + 125。
4. `data/*` 三个数据文件与 `风场数据/风电场.xlsx`：本次改造**一个字节都不动**。
5. 8 项指标口径：平均风速、尾流后风速、理论发电量、尾流损失、上网电量、等效小时、综合折减、容量系数。
6. `BASEMAPS` 的 URL / maximumLevel / 逐源亮度对比度。
7. 道路与集电线路的 MST 拓扑、场区凸包边界、升压站与测风塔的示意位置。

## 9. 技术风险

| 风险 | 应对 |
|---|---|
| 重写 UI 时误改 `heightAt` / ENU 公式 | 几何代码整段复制，改完用 sha256 与基线比对 `data/*`，并在浏览器里逐台核对经纬度与高程 |
| 面板浮层与看板争位 | 看板限位区改为按面板实际宽度动态计算 |
| 演示模式与普通模式状态串味 | 状态机显式建模 `mode: 'view' \| 'present'`，进入时快照面板状态，退出时还原 |
| 全屏切换后 Cesium 画布尺寸不刷新 | 监听 `fullscreenchange` 调 `viewer.resize()` |
| 双击与单击事件冲突 | 单击用 `LEFT_CLICK`，双击用 `LEFT_DOUBLE_CLICK`；Cesium 保证单击先触发，用 220 ms 去抖合并 |

## 10. 回归测试方案

1. **数据层**：重构前后 `sha256sum data/*` 必须完全一致（数据未改动即证明未篡改）。
2. **渲染层**：浏览器内读取每台塔筒实体的 `position` 与 `heightAt`，与基线经纬度/高程逐台比对，容差 0.1 m。
3. **展示层**：读取详情面板文本，核对 8 项指标与 `site-data.js` 原值一致。
4. **功能**：底图 8 源逐一切换、图层 5 项开关、视角 3 预设、演示模式 5 场景进出、全屏进出、Esc 关闭弹层。
5. **视觉**：1920×1080 / 1600×900 / 1366×768 三档截图，检查遮挡、截断、对比度、无横向滚动条。
6. **异常**：底图源失败回退、数据文件缺失提示、影像加载超时。
