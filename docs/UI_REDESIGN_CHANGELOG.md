## 三、逐项改造

### 1. 设计系统（`index.html` 顶部 `:root`）

- 颜色、圆角、阴影、间距、字号全部收敛为 CSS 变量，组件只引用变量。
- 主色由高饱和荧光青 `#22d3ee` 改为较低的 `#4cc2f1`，仅用于选中态、关键数值与主操作。
- 状态色语义化：`--ok` 绿 / `--warn` 琥珀 / `--bad` 红，只用于数据判定，不做装饰。
- 圆角三级（5/8/12 px）、阴影两级、过渡统一 `--dur: .16s`。
- 支持 `prefers-reduced-motion`。

### 2. 信息架构

- 顶栏：项目名 + 产品标识 + 三个页签（场址总览 / 机位分析 / 地形与工程）+ 演示模式 / 图层 / 全屏 / 复位。
- 左侧面板：只承载当前页签内容，宽 352 px（≤1560 收至 326，≤1320 收至 300，≤1100 收至 288）。
- 右侧抽屉：仅在选中机位时滑出，360 px，关闭后场景恢复全宽。
- 底部控制坞：视角三段控件 + 图例 + 数据来源/加载状态，单行高度约 40 px。

### 3. 三级信息分层

| 层级 | 位置 | 内容 |
|---|---|---|
| 一级 项目概览 | 左侧「场址总览」 | 装机、台数、年上网电量、等效小时（四张指标卡）+ 场址条件 + 机组参数 |
| 二级 场址分析 | 左侧「机位分析」/「地形与工程」、抽屉 | 机位清单（排序 + 区间归一化条形 + 统计摘要）、地形统计、间距校核、单机指标 |
| 三级 技术信息 | 「地形与工程」底部折叠块、抽屉「工程详情」折叠块 | 坐标系统、投影反算残差、DEM 与实测高程差、E/N、经纬度、坡度 |

三级信息默认折叠，业主首屏看不到。

### 4. Cesium 场景

- **自动取景**：新增 `fitCamera()`，以场区控制范围顶点为拟合对象，迭代调整「距离 + 视点水平偏移」，使投影外接框贴合可视安全区（扣掉左侧面板与底部控制坞）。不写死任何相机数值。
  - 修复了两个缺陷：① 投影矩阵需 `scene.render()` 后才更新，否则测的是上一帧（首版因此偏近 20%）；② `lookAt` 对准画布中心，而左侧面板占了 352 px，导致内容整体偏左（首版 B100 被面板遮挡）。
- **相机预设**：全场（-42°）/ 顶视（-89.5°）/ 斜视（-26°），均走同一拟合逻辑。
- **单机视角**：距离 5.0R，瞄准 0.72 倍轮毂高，保证塔基与叶尖同时入画（改造前塔基被裁）。
- **雾密度** 0.000045 → 0.000060，弱化远场地形边界硬线。
- **影像亮度** 按源重调（卫星 1.30 → 1.24），配合新面板底色。
- 保留：地形分级融合、CSV/DEM 数据源、8 个底图源、道路与集电线路 MST、凸包边界、叶轮动画。

### 5. 机位显示三态

| 状态 | 触发 | 表现 |
|---|---|---|
| 全场浏览 `overview` | 默认 / 场址总览页签 | 仅编号 chip |
| 机位分析 `layout` | 切到「机位分析」页签 | 编号 + 上网电量两行 chip |
| 单机详情 `detail` | 进入单机视角 | 选中机展开数据卡（含 E/N 坐标），其余 chip 淡化 |

标签避让逻辑保留并改进：安全区按面板/抽屉实际宽度动态计算，避让后仍做上下限位；数据卡贴到顶栏下方时自动隐藏引线（改造前会被顶栏裁掉 1/3）。

### 6. 交互

- 场景单击 = 选中（不移动相机）；双击 = 选中 + 进入单机视角。用 240 ms 去抖合并 Cesium 的 `LEFT_CLICK` 与 `LEFT_DOUBLE_CLICK`。
- 清单单击 = 选中 + 定位（列表作为导航控件，语义与场景点击区分）。
- 空白处单击 = 取消选中；`Esc` 依次关闭弹层 → 退出演示 → 取消选中。
- 快捷键：`R` 复位、`F` 全屏、`←/→` 演示模式翻页。
- 「进入单机视角」按钮在单机视角下自动隐藏，不留无效控件。

### 7. 演示模式

5 个场景：项目总览 → 场址与地形 → 机位分布 → 典型机位 → 回到全场。

- 进入后隐藏两侧面板、页签与操作组，仅保留项目名、场景控制条（←/›/退出）与左下核心指标条。
- 每个场景只做一次相机飞行 + 一次选中变更，无自动播放，无强制等待。
- 随时 `Esc` 或「退出演示」返回，退出后恢复普通布局并复位到全场。

### 8. 响应式

- 1920×1080 / 1600×900 / 1366×768 三档实测（见验收记录）。
- 面板宽度、字号、指标卡字号按断点收敛；`docW === winW`，无横向滚动。
- 全屏切换后 `viewer.resize()`，避免画布尺寸不刷新。

### 9. 加载与异常

- 6 步加载文案（引擎 → 场景 → 机组 → 工程要素 → 面板 → 瓦片）。
- 瓦片未加载完时在底坞显示「影像加载中…」，避免把 LOD 色块误认为影像缺陷；遮罩最长 18 s 后放行。
- 影像源失败 8 s 内 ≥4 个瓦片报错 → 自动回退卫星影像并提示。
- Cesium 未加载、数据文件缺失 → 全屏错误页给出修复步骤，不暴露堆栈。

## 七、已知问题

1. **影像瓦片加载期间会出现明暗色块**。这是在线影像的 LOD 分级结果，加载完成后自行消失（已在底坞加「影像加载中…」提示）。切换相机后约 5–15 s 稳定，取决于网络。
2. **低视角地平线处地形较"平"**。DEM 只覆盖到 ±14 km，远处按基准高程平滑收敛；已用雾弱化，但达不到无限地形效果。
3. **叶片为简化 box 几何**，远看轮廓正确，近看无翼型与预弯（改造前即如此，本次未改）。
4. **无实时数据**。页面中所有数值为前期实测/计算结果，界面已明确标注"不含实时监测数据"。
5. **移动端未适配**。本项目面向桌面与会议室投影，窄屏仅保证不破版，不做交互优化。

## 八、下一阶段建议

1. 接入机型功率曲线与折减构成拆分（尾流/控制/电气/可用率），替换当前"综合折减 25%"的单一口径。
2. 增加施工要素图层（道路等级、吊装平台尺寸、集电线路回路编号），数据具备后再上图层开关。
3. 演示模式补充"自动播放 + 暂停"，并支持导出 PDF 汇报页。
4. 若需离线汇报，考虑将常用视角的影像瓦片预缓存为本地瓦片包（注意影像许可）。
5. 机位数量增至数十台时，叶片 CallbackProperty 的每帧开销会线性增长，届时改为单 Primitive 合并几何。

# V3 · 暗色玻璃质感与三面板可收起

## 九、本次改动

### 9.1 视觉基底：从"半透明面板"到"玻璃材质"

原实现是 `rgba(14,21,32,.94)` 单层色块，几乎不透光，看上去是"深色卡片"而不是玻璃。改为三层叠加：

1. **渐变底**：`155deg` 冷调渐变（`rgba(28,42,58,.74)` → `rgba(12,18,27,.72)` → `rgba(7,11,17,.80)`），保留 20%–28% 透光率；
2. **模糊**：`backdrop-filter: blur(30px) saturate(150%)`；
3. **纹理**：`::before` 叠加 140 px 噪点（`feTurbulence`，磨砂颗粒）+ 30 px 网格线 + 顶部 26% 渐隐白光（玻璃边缘反光）。

边框与阴影：`inset 0 1px 0 rgba(255,255,255,.09)` 内高光 + `inset 0 0 40px -16px rgba(76,194,241,.22)` 青色内发光 + 外投影。左上角加 30 px 的 L 形青色装饰线。

顶栏改为 `blur(22px)` 玻璃，底部加一条中间亮、两端透明的发光线。

### 9.2 三块面板全部可收起

| 面板 | 收起按钮 | 收起后 |
|---|---|---|
| 左侧信息面板 | 标题栏 `‹` | 屏幕左缘留竖向「面板」把手 |
| 右侧详情抽屉 | 标题栏 `›`（与原 `×` 区分） | 屏幕右缘留竖向「详情」把手 |
| 底部控制台 | 右侧 `⌃` | 收为 42 px 细条，只留标题 + 视角预设 |

状态统一存于 `state.ui = { left, dock, right }`，由 `applyChrome()` 一次落地，避免多处各管一段导致状态漂移。

`usableRect()` 与 `labelBounds()` 改为读 `collapsed` 类而非 `hide`，收起面板后自动取景/标签避让会跟着让位。抽屉的 `×` 仍是"取消选中"，`›` 只是"折叠视图"，两者不混用。

### 9.3 图层与底图从弹层移入底部控制台

原「图层」按钮弹出 312 px 浮层，需要两步才能改一个开关。改为底部一等控制台：

- **列 1 底图源**：8 个源按 4 × 2 网格排布，卡片显示短名与分辨率，选中项带左侧青色光条；
- **列 2 图层**：5 个开关（风机模型 / 机位编号 / 场区控制范围 / 场内道路 / 35 kV 集电线路）；
- **列 3 场景**：叶轮旋转开关 + 转速滑块（0.2–2.0×）。

控制台宽 1060 px（窄屏自适应），**横向居中于左右面板之间的可用区**（`syncDock()`），并随抽屉开合自动重排，不压面板。顶栏「图层」按钮改为「场景控制」，只做展开/收起，状态与面板同步。

`#layersPop` 弹层、`openPop/closePop/renderLayersPop` 全部删除，避免两套 UI 并存。

### 9.4 顺带修正

- **单机取景按可用高度反算**：原固定 5 倍叶轮半径，控制台占下部 268 px 后塔基被压住。改为按 `ch - dockH` 的可用高度求垂直视场半角，反算距离与俯角，并把视线中心上移到可用区中心。实测塔基 y=501、叶尖 y=109，可用区 64–552，整机居中。
- **选中数据卡贴抽屉左缘**：原逻辑在抽屉打开后把右侧标签整块隐藏，选中机却看不到标注。改为水平限位（clamp），卡片贴到抽屉左缘。
- **数值与单位不再换行**：`.kpi-v` 加 `nowrap`，`b` 设 `flex:none`，抽屉四宫格单位不再掉行。
- **侧栏高度自适应内容**：去掉 `bottom:12px`，改 `max-height:calc(100% - 24px)`，内容少时不再拉满全屏留大片空白。
- **排序按钮被挤掉**：`.link-btn` 补 `flex:none`，避免被 `hint` 长文本压成 0 宽。
- `scene.globe.maximumScreenSpaceError` 由默认 2 降到 1.6，近景地形更细。
- 清理 `vRelief` 死引用（DOM 已删）。

原来一行是「左文字 + 右开关」两端对齐，中间大片空白。改为**整块即按钮**：

### 18.4 风机模型放大（1.0–5.0，默认 2.0）

底栏「场景」列新增「模型放大」滑块，绿色滑块与转速的青色区分。

**实现**：Cesium 的 Entity 几何没有统一 `scale`，只能按新尺寸重建。
`buildTurbine()` 内所有整机尺寸乘以 `SC`：塔筒长度与上下半径、机舱三轴与偏移、
轮毂半径、叶片分段长度与截面、基础半径。**塔基坐标与场地要素（吊装平台、箱变）不缩放**，
所以放大后机位平面位置仍准，只是"长高了"。

配套调整：
- 标签锚点 `ground + (HUB_H + ROTOR_R) * SC + 8`，随模型升降；
- 单机取景的 `objH` 与相机高度同样乘 `SC`，放大后仍能整机入画；
- 拖动时只更新数值，停手 180 ms 后重建（8 台 × 约 20 个实体，重建约数十毫秒）；
- `change` 事件里再同步一次数值——方向键调值时不触发 `input`，只靠 `input` 会漏更新。

# V6 · 35 kV 集电线路杆塔建模（实测塔位）

## 二十五、新增数据与流水线

1. **`src/import_gridline.py`**：读 `风场数据/集电线路.xlsx`（73 基塔位，X 为 6 位东坐标**不含带号**，
   与机位表的 8 位含带号不同，按数值位数判定补 38 带号），转换经纬度 + 局部 ENU（**沿用机位重心原点**）。
   输出 `data/gridline.json`。
2. **线路拓扑**：按塔号规则成 6 条链（AB 30 / A 17 / A3 7 / B 15 / B7 4 / B10 3），链间连接
   AB30→A1（编号规则）+ B1→最近塔（距离判定）。8 台机位各有一基末基塔（距离 1～109 m）接入。
3. **塔型判定**（推断值）：链首末 / 转角 >15° / 支线分歧 / 耐张段 >2 km → 耐张塔，否则直线塔。
   结果 30 耐张 + 43 直线。
4. **塔位高程**：`fetch_dem.py` 增加塔位点采样（ASTER 30 m，73 点 1 批），独立缓存
   `dem_points_cache.json`；场景内塔基取分级网格高度（贴地），ASTER 点值作校核。
5. **`src/make_tower_glb.py`**：生成塔型参数 `data/tower-types.json`（横担/挂点/根开/基础），
   前端据此建模，不硬编码任何塔型尺寸。

## 二十六、L1 网格扩展（数据精度）

塔位最远距原点 8.3 km，原 L1（±6 km）覆盖不到，塔基高程与 ASTER 点采样最大差达 **50.2 m**。
把 L1 从 ±6 km 扩到 ±12 km（步长 300 m 不变），差值降到 **21.5 m**（平均 5.4 m）。
机位都在 ±6 km 内，实测 Z 与 DEM 差值不受影响。

## 二十七、杆塔建模（Entity 四棱台拼装）

**关键取舍**：最初采用单文件 glTF（每基 1 个实体、scale 可直接改、可做格构细节），但实测
**Cesium 的 Model 在 SwiftShader 软件渲染下不绘制**——模型 `ready=true`、位置正确、包围球正确，
画面却始终无塔；改用 `Cesium.Model.fromGltfAsync` 单测也验证加载成功但不可见。为跨环境一致、
且能在无头环境验收，改回 Entity 几何拼装：

- **塔身**：`cylinder slices:4` 变截面四棱台，绕天顶转 45° 使棱落在对角（对齐角钢主材方位）；
- **横担**：两层细长 box（下横担边相 + 上横担中相短担），沿横担方向（线路切线顺时针 90°）；
- **基础**：方形混凝土 box（露头 base_h）；
- **绝缘子串**：边相横担端部竖直细柱，连接横担与导线挂点。

每基约 5 个实体（塔身 1 + 横担 2 + 基础 1 + 绝缘子 2），73 基约 365 实体。塔型（直线/耐张）
由 `def.arms / b_bot / b_top / h_body` 驱动，横担臂长耐张塔更大。

## 二十八、导线

按 `spans`（70 档）逐相生成 3 根导线，挂点 = 塔基 + 横担方向 × 臂长 × 倍率，高度 = 塔基 +
挂点标高 × 倍率；弧垂 f = 0.024 × 档距（350 m 档距 ≈ 8.4 m），抛物线 12 段采样。
颜色 #2fe0a0（与图例一致），`distanceDisplayCondition` 0–24 km。

## 二十九、放大联动

「模型放大」倍率（1.0–5.0）同时作用于风机、杆塔、导线：`applyModelScale()` 里
塔重建（四棱台尺寸 ×SC）、导线重建（挂点高度 ×SC）、风机重建。实测 2→4→2 切换
实体数恒稳、无残留。

## 三十、踩坑记录

1. **glTF 在 SwiftShader 下不渲染**（本版最大坑）：模型 ready、位置、包围球全部正确，画面却无塔；
   红色 REPLACE 材质 + 15 倍放大也看不到。定位手段：`Cesium.Model.fromGltfAsync` 单测确认加载成功、
   遍历 `scene.primitives` 找到 73 个 `ready:true` 的 Model 实例、读 modelMatrix 确认位置正确。
   最终结论：无头软件渲染不支持 Cesium Model 的绘制，只能改 Entity 拼装。
2. **tower-types.json 漏 `arms` 字段**：第一版输出没写 arms，前端 `def.arms.forEach` 抛
   `reading 'forEach'`，报错被 onerror 吞掉只显示在日志。补上 arms/base_size 后解决。
3. **浏览器缓存旧 site-data.js**：改完数据文件后实体数不对，加 `?v=N` 破坏缓存才生效。
4. **绝缘子串位置初版用 ENU x 轴偏移**（错）：绝缘子应在横担方向偏移，初版沿正东偏移，

## 三十三、实现

1. **`js/tower-j1.js`**（新增）：把 `tower-j1-35kv.html` 的 `buildMembers()` +
   `angleGeometry()` 提取为独立模块，去掉 Three.js 依赖，直接输出
   `positions / normals / indices`（局部坐标，x=横担方向、y=线路、z=向上）。
   原 Three.js 模型 y 向上，统一绕 x 轴 +90° 变换 `(x,y,z)→(x,-z,y)`，行列式 +1、绕序不变。
2. **绝缘子串简化**：原 LatheGeometry 24 段伞裙每片约 500 三角形，3 处 × 3 片将额外增加 4500 面；
   改为六棱柱扁盘（每片 24 面），共 288 面，保留"悬垂串"的视觉符号。
3. **`app.js` 改造 `buildTowers()`**：每塔一个 `GeometryInstance`，`modelMatrix = ENU × rotZ × scale`，
   73 个实例合并为一个 `Primitive`（`PerInstanceColorAppearance({flat:false})`，法线光照）。
4. **导线挂点**改用 `TowerJ1.HOOKS`：下横担 ±2.55 m 挂边相、上横担 +2.0 m 挂中相，
   标高 = 横担标高 − 绝缘子串长（24.0−1.005 与 27.6−1.005）。导线弧垂系数不变。
5. **交互**：`scene.screenSpaceCameraController.minimumCollisionTerrainHeight` 由默认 15000
   降到 60 —— 塔高 30.7 m，默认阈值会把相机推到 300 m 以上，无法贴近观察。

## 三十四、踩坑（按发生顺序）

1. **`boundingSphereCV` 缺失导致渲染中断**：Cesium 的 `Primitive` 在 `scene3DOnly=false`
   时无条件读 `geometry.boundingSphereCV.center`，自建 `Cesium.Geometry` 没有该字段即抛
   `Cannot read properties of undefined (reading 'center')`，整个场景停止渲染。
   先给每个 geometry 补一个 `{center, radius}` 普通对象绕过；同时 viewer 设 `scene3DOnly: true`。
2. **Uint32 索引静默不绘制**：顶点 17364 < 65536，但用 `Uint32Array` 索引时 SwiftShader
   不支持 `OES_element_index_uint`，几何整体不出现且无报错。改 `Uint16Array`。
3. **73 个实例共用同一个 boundingSphere 对象**：Cesium 合并实例时用
   `BoundingSphere.transform` **就地**变换，后续实例拿到已被变换过的球，逐级偏移后被判视锥外。
   每个实例必须 `Cesium.BoundingSphere.clone()`。
4. **横担在远景下不可辨是正常的**：J1 下横担仅 ±2.55 m，塔高 30.7 m，比例 1:6，
   与"简化塔横担很长"的直觉不同，属图纸本身的比例。
